# Deploying Keepsake to Render

Keepsake ships as a Render **Blueprint** (`render.yaml`): a free Postgres, the NestJS API (Node web service), and the Angular frontend (static site). The API URL and CORS origin are cross-wired between the two services, so there are **no URLs to hand-edit**.

## Prerequisites

1. A **Render account** (https://render.com) and a **GitHub/GitLab** account.
2. Render deploys from Git — **this project is not a Git repo yet**, so you must push it first.

## Step 0 — Push to GitHub

```bash
cd keepsake
git init
git add .
git commit -m "Keepsake: initial commit"
# create an empty repo on GitHub first, then:
git remote add origin https://github.com/<you>/keepsake.git
git branch -M main
git push -u origin main
```

> ⚠️ Before committing, confirm `git status` does **not** list `apps/api/.env` or `apps/api/.env.test`. The updated `.gitignore` excludes them — those files hold your `JWT_SECRET` and DB credentials and must never be pushed.

## Step 1 — Create the Blueprint

1. Render Dashboard → **New** → **Blueprint**.
2. Connect the repo you just pushed. Render reads `render.yaml` and shows three resources: `keepsake-db`, `keepsake-api`, `keepsake-web`.
3. Click **Apply**. Render will, in order: provision Postgres → build the API (generate client → compile → `prisma migrate deploy` → seed) → build the Angular static site.

First deploy takes a few minutes. When done you get two URLs, e.g. `https://keepsake-web.onrender.com` (open this) and `https://keepsake-api.onrender.com`.

## Step 2 — Log in

The build seeds demo accounts (password `password123`):

| Email | Role |
|---|---|
| `admin@keepsake.local` | admin (everything, incl. Integrations) |
| `accountant@keepsake.local` | accountant |
| `auditor@keepsake.local` | auditor |
| `viewer@keepsake.local` | viewer |

> 🔐 `password123` is a demo default. For anything beyond a demo, change it (see below) and rotate `JWT_SECRET`.

## What the Blueprint wires up

- **API env:** `DATABASE_URL` (from the DB), `JWT_SECRET` (generated by Render), `WEB_ORIGIN` (the web service's host → CORS allow-list), `RECONCILE_INTERVAL_MS=300000`.
- **Web build:** `API_BASE_URL` (the API's host) is baked into the bundle by `apps/web/scripts/set-api-base.mjs` before `ng build`; a rewrite rule serves `index.html` for client-side routes.
- **Health check:** the API exposes public `GET /health`; Render uses it to gate the deploy.

## Free-tier caveats

- The **API sleeps after ~15 min idle**; the first request afterward cold-starts (~30–60 s). The reconcile scheduler pauses while asleep.
- **Free Postgres is deleted 90 days** after creation. Upgrade the `plan:` fields in `render.yaml` to `starter` for always-on + persistent data.

## Redeploys & migrations

Every `git push` to `main` triggers a rebuild. The API build runs `prisma migrate deploy` (applies any new migrations) and re-runs the idempotent seed. New Prisma migrations are just committed under `apps/api/prisma/migrations/`.

## Changing the demo password (optional)

After the first deploy, from the API service's **Shell** tab:

```bash
pnpm --filter api exec tsx -e "import {PrismaClient} from './src/generated/prisma/client'; import {PrismaPg} from '@prisma/adapter-pg'; import argon2 from 'argon2'; const p=new PrismaClient({adapter:new PrismaPg({connectionString:process.env.DATABASE_URL})}); const h=await argon2.hash(process.env.NEW_PW); await p.user.updateMany({data:{passwordHash:h}}); console.log('updated');"
```

(set `NEW_PW` in the shell first). Or just delete the seeded accounts and register your own.
